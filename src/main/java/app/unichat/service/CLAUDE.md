# service — notes for Claude

The API the UI uses, demo mode, and what the person keeps (preferences, folders).

- `service/ChatService` — the only API the UI uses (made of small role interfaces; take the narrowest one). Live model objects, listeners on any thread (UI marshals with
  `Platform.runLater`, coalesced in `MainView` by `ui/Throttle`). `MockChatService` = demo mode. `BridgeAccess` = what only bridge-backed services add.
- Data dir files: `preferences.json` (per-chat archived/muted/favorite/lowPriority/pinned + folders; `service/PreferencesFile`), `settings.properties`,
  `media-library.json` and `media-library/` (a copy of each favourite sticker/GIF, `matrix/SavedMedia`) and `writing-style.md` (how the person writes, for AI drafts) travel with the person (copy them to a new machine); `session.properties` (token, `matrix.*`, `server.*`, `window.*`; `Settings.staysOnThisMachine`
  decides, older keys migrate out of settings.properties), `server-seen.json`, `writing-style-corrections.json` and `writing-style-history/` (`assist/CLAUDE.md`) stay. An older version will ask you to log in again, because the session moved to session.properties; nothing is lost. `preferences.json.bak` is the version before the last save, tried when the main file is damaged. Saves happen on a coalescing daemon thread (never on the caller's, which may be the UI or hold `proc`), so a test reading the file calls `flush()` first; `ChatSession.stop()` flushes, and quit, logout and a shutdown hook in `UnichatApp` all reach it. Preference rules (`matrix/RoomPreferences`): the file wins; a field the
  person never touched follows the server; a server false counts only if the same server (identity `homeserver|deviceId`) said true, so a fresh server doesn't
  erase copied choices. Only the mute rule still goes to the server (unread counts come from it). Chat identity across servers: `service/ChatKeys`,
  `<protocol>:<channel.id>`. `service/ChatFolders` is the role for folders (`FolderActions`, `FolderForwarding`); a folder can be a favorite (`Folder.favorite`, in preferences.json; its menu), shown at the end of the favorites row with a folder tile that opens it. The favorites are one row, never wider than the column nor scrolled (`ui/chats/FavoritesRow`: tiles narrow down to the avatar's width, then the last place is "+N" and opens the Favorites view). Favorite tiles are up to 4.4 em wide, names centered and cut with "…" (`Formats.favoriteName`: the first word unless it's under 4 letters; `FavoritesRowUiTest`); `ui/chats/FolderView` (+ `FolderRows`, `FolderDialogs`) shows them, each folder a row as tall as a chat's (tile, name, time and last message of its most recent chat).

## Lessons
- `PreferencesFile` had five jobs in 725 lines. The background writer is `support/BackgroundWriter` (shared with `Settings`), `server-seen.json` is `ServerSeen` and the damaged-file recovery (`.bak`, `.bad-<time>`) is `PreferencesRecovery`; both are guarded by `PreferencesFile`'s lock. Its tests didn't change.
- `DemoMedia` drew a picture straight into its file, and a caller that found the file there meanwhile took it half written: the info panel's avatar and the photo viewer ask for the same picture at once, and on Linux the viewer showed "couldn't open" (`InfoAvatarUiTest` failed every CI run once the test order changed). Making a file is one at a time (`synchronized`) and whole (`SafeFile`) (`DemoMediaTest`, eight callers at once, which failed on the Mac too).
