# autosave — notes for Claude

Saving what others send in a chat, by kind, as it arrives and back through its past. The rules, commands and map are in the root `CLAUDE.md`.

- Saving what a chat receives (`autosave/AutoSave`): the gear in a chat's header opens its options (`ui/ChatOptions`), where it's turned on and each kind chosen apart (`model/SaveKind`: photos, videos, audio, documents, GIFs, link videos; never stickers), in preferences.json (`Flag.AUTO_SAVE` plus one "left out" flag per kind, so what was on before kinds existed stays all; `ChatPreferences.setAutoSave/autoSaves`). It saves as soon as messages are there, chat opened or not: every `messagesChanged` (live or catching up after sleep or a restart) saves what others sent after the last one saved (`autosave/SavedUpTo`, `autosave.json`, exact instants; turning it on starts now: never the history). Started with the service (`UnichatApp.showMain`), not the window. Media through `FileNames` (as "Guardar como…", never overwriting), links (`support/Urls.in`) with `video/YtDlp` (pinned, downloaded on first use; one video, never the playlist, up to 1080p, the link after `--`; its own error line is the reason). Folders (`autosave/SaveFolders`, `autosave.` keys stay on this machine): a base in Ajustes → Redes (`~/Downloads/Unichat` unless chosen; `-Dunichat.autosaveDir`, which surefire points into target/), one folder per chat under it or a chat's own from its options. `AutoSave.Progress` feeds the menu-bar icon (`Notifier.setDownloadProgress`: a ring that fills, spinning until the first is done; the helper's `progress` command, the AWT tray draws it too) and the notices: done (how many, from which chat) and, always, what failed with why (no space, measured where it was going; no permission; yt-dlp's reason). Ajustes → Notificaciones turns the ring and the done notice off (`downloads.trayProgress`, `downloads.notifyDone`). The options' "Lo anterior" explores the past (`AutoSave.explore`): page by page back to the beginning (`ChatReader.loadOlder`), each page a job of its own so what arrives isn't kept waiting, only the kinds chosen, older than what was saved live, continuing where it stopped (`SavedUpTo.Back`); what's gone is counted and told once, no space stops it. The saved files are an archive: a message deleted, seen once or expired never deletes its copy.
