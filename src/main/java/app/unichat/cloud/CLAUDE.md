# cloud — notes for Claude

The person's own storage account (pCloud, Icedrive, Nextcloud…). The rules, commands and map are in the root `CLAUDE.md`.

- `Storage` is the account however it's reached: `WebDav` (Icedrive, any other), or `PCloudApi`, pCloud's own API (stat, createfolderifnotexists, uploadfile with nopartial, getfilelink; token in a Bearer header, never in an address), because pCloud's WebDAV refuses a login with two-step verification on (it just never answers: every question to a server waits at most `WebDav.ANSWER`). `PCloudLogin` signs in in the browser (OAuth 2 token flow): pCloud's page, then `http://localhost:43117/pcloud` (fixed: the address registered with the app), whose page passes the "#" part on to `/pcloud/done`; `state` ties the answer to the request; only `*.pcloud.com` hosts are trusted with the token. The app's Client ID: `PCloudLogin.CLIENT_ID` once Unichat's app is registered, or `cloud.pcloudClientId` from Ajustes → Nube. Tests: `FakePCloud`. `DropboxApi` (API v2, app-folder access: paths start in Dropbox/Apps/<app>): `DropboxLogin` signs in with OAuth 2 + PKCE (no secret in the app; Dropbox sends a code to `http://localhost:43117/dropbox`, exchanged with this sign-in's own verifier for a lasting refresh token, kept as the account's secret); each call carries a short-lived token made from it again when Dropbox answers 401; names go in the `Dropbox-API-Arg` header as ASCII-escaped JSON (accents, emoji); files over 150 MB go up in an upload session. App key: `DropboxLogin.APP_KEY`, or `cloud.dropboxAppKey` from Ajustes. Both browser sign-ins share `Loopback` (127.0.0.1, port 43117, state). Tests: `FakeDropbox`.

- `WebDav` (PROPFIND/MKCOL/PUT/GET; `stamp` = ETag or date, so a round downloads only what changed), `CloudAccount` (service, address, login and secret: `cloud.` keys stay on this machine; `Unichat/Ajustes`, `Unichat/Multimedia`), `Cloud` (one round a minute and one after anything's saved, on its own thread; `Status` for Ajustes → Nube, `ui/CloudPage`).
- `SyncedPart`: one thing kept the same on every computer, as one file: three versions (here, the account's, the last agreed `cloud.base.<name>`); only one side changed → it goes to the other; both → the newer; a computer new to the account takes what's there. After adopting, the agreed hash is what this computer holds (agreeing on the account's own sent it back up forever). Two parts: the settings (`Bundle`: portable settings minus `panel.`, and `preferences.json` minus what only follows the server) and what the AI learned (`writing-style.md`; pending corrections stay here).
- Applied live, never a restart: settings through `Settings.replacePortable`, then `ui/SyncedSettings` (what Ajustes does for the few read once: theme, AI buttons, global shortcut, Dock, notifications label, update check, language last); preferences through `ChatPreferences.adoptPreferences`. `SyncedSettingsUiTest` has a proof for every setting key in the source, and fails for a new one without.
- Media (`MediaUpload`): each chat's saved folder goes up until all of it is there: a file that fails waits its own turn again (1, 2, 4… up to 60 minutes, forever, `Retry`) without holding the others back. Each upload is checked against the account's copy (`Storage.info`: size, and a checksum where the service gives one: pCloud's SHA-1, Dropbox's content hash; WebDAV only the size; computed here by `Checksums`). Once a day and on "Verificar ahora" everything uploaded is checked and repaired, the bigger copy winning (`Checksums.decide`: damage cuts files short, so a file damaged here is restored from there and never damages it; same size and other content: neither is touched, the person is told). Done files in `cloud-uploaded.txt`; nothing there is ever deleted; hidden and ".part" files wait. A round reports each step (`Cloud.Activity`: settings, what the AI learned, uploading or checking file n of m) for Ajustes → Nube.
- Not in the demo (its chats would reach the person's account), except for a snapshot of the page. Tests use `FakeDav` (an in-memory WebDAV on 127.0.0.1).
