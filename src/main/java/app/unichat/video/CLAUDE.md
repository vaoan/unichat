# video — notes for Claude

ffmpeg, yt-dlp, stickers and picture conversions. How they show on screen (players, viewers, animations and their memory limits): `ui/media/CLAUDE.md`.

- `native/build-gif2webp.sh` — libwebp's `gif2webp` (and `anim_dump`, which `video/AnimDump` runs to decode animated WebP: TwelveMonkeys gets some lossy frames' colours wrong, black blotches; it's the fallback) built from pinned sources (with GIFLib; Google's Mac binary needs macOS 15) and shipped in `app/server/` (Windows: Google's build, pinned in package.ps1);
  `matrix/StickerConverter` uses it when a chat's room_features refuse a sticker's MIME (GIF → WebP on WhatsApp), keeping `fi.mau.bridged_sticker` when the sticker is the chat's own network's (`MessageSender.ownSticker`): Telegram's bridge first rejects a type the chat doesn't take (image/gif), then sends the original from its pack; without the mark it passes the file through its ffmpeg, which fails without a WebP encoder (Homebrew's). A sticker from another network to Telegram (`StickerConverter.forTelegram`, whatever room_features say) goes as a still PNG, which the bridge encodes itself, or, an animated GIF, as a VP9 WebM video sticker (`WebmStickers.fromGif`): the bridge sends PNG, JPEG, WebM and Lottie on as they are and everything else, WebP included, through that ffmpeg.
  The other way, a WebM sticker (Telegram's video stickers) to any other network goes as an animated GIF (`StickerConverter.asGif`, `WebmStickers.toGif`; then WebP if the chat wants it): Discord shows a WebM as a video to press play on, while it plays a GIF and an animated WebP by itself; without ffmpeg the WebM goes as it is.
  Ajustes → Redes (`<network>.animatedStickers` = STICKER|GIF|VIDEO) can send them as mp4 instead (`GifFrames` +
  JCodec, pure Java).
- `VideoTranscoder.makePlayable`: a saved video as H.264/AAC in its place (what ffmpeg says of it, `playsEverywhere`; no ffprobe, only ffmpeg ships), used on what a link saves (`autosave/LinkSaver`). `YtDlp` keeps the pinned yt-dlp ready (running it is InstaTray's engine); `GalleryDl` finds the person's gallery-dl.

## Lessons
- ffmpeg tells a file's format by its content: a "video" from a chat that is really an HLS playlist (or a concat list, a DASH manifest) names other files, and `-protocol_whitelist file` still let it read them into the output that's saved and uploaded. Files from others go in through `Ffmpeg.input`, which refuses those (`FfmpegInputTest`; `.claude/lessons.tsv` `ffmpeg-input`). A forced format (`-f matroska`, `-f s16le`) doesn't probe and is fine.
- ffmpeg calls a picture "Video" too (GIF, WebP, APNG, PNG, JPEG as mjpeg): `makePlayable` turned every picture gallery-dl saved from a link into a one-frame MP4. Pictures are told by the format ffmpeg read them as (`VideoTranscoder.picture`: gif, apng, image2, the "…_pipe" image readers), never by the codec, since a camera's MJPEG in an AVI is a video (`VideoTranscoderTest`).
- `BigPictures` and `SendablePhotos` built their command list with `Ffmpeg.whenNeeded`, which downloads ffmpeg (~28 MB), before `sips` (always on a Mac) had a try. Ways are tried lazily (`PartFile.sipsThenFfmpeg`): ffmpeg is looked for only when sips isn't there or failed (`BigPicturesTest`).
- "Run each way into a .part, move it into place" was written five times: `PartFile.firstOf` (hidden, ".part" kept in the name for the cache, autosave and the cloud, extension last for ffmpeg). Pinned downloads are `PinnedTool.install`, the computer's build `Os.pick` (also `CloakTool`).
