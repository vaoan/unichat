# assist — notes for Claude

Drafts and corrections with the person's own AI program.

- `assist/` + `ui/AiReplyButton`, `AiReplyPage` — AI reply drafts, and correcting what's written (`FixPrompt`: only that text goes, no chat, instructions or folder; undoable with ⌘Z), through the person's own `claude` or `codex` (`AiEngine`, prompt on stdin, `ai.*` settings, off by default). Only ever text in the composer, never sent by itself; it goes in as an edit (`replaceText`, not `setText`, which forgets the undo history), so ⌘Z brings back what was written before it (`DraftUndoUiTest`): a draft built on it can still change what the person meant. A draft is one call to the program, so it's fast (~5 s; ~17 s when it searches the web): the voice notes it answers (`ReplyPrompt.voiceNotesToHear`: the chosen one and the newest since my last message, at most 6; `ai.voiceNotes`, on by default) are transcribed ahead, when the chat opens or one arrives (`Composer.hearAhead`, `Transcripts.requestAhead`, which never retries a failure), and `AiReplyButton.heard` only waits for what's left (3 minutes in all); they go in the prompt as their text, so `AiReplyButton.Request` carries a supplier, run off the UI thread. The prompt also says when it is now (day, time and time zone) and how long ago the last message was (`ReplyPrompt.when`), so a late reply doesn't sound instant. The draft uses how the person writes as learned so far; learning (`ai.learnStyle`, on by default) comes after each draft, in the background (`Composer.learnAfter`, one at a time, ~10 s): when there's something new (corrections or newer messages of mine in the chat), `assist/StyleLearner` has the same program update `writing-style.md` (`StylePrompt`: at most 40 bullets / 3 000 characters, told to it with the file's current size, style only, nobody else's data; an answer only too long is sent back once to be shortened (`StylePrompt.shorten`), any other failure keeps the old file and the log says why (`StylePrompt.problem`); 2 minutes), from my last 30 messages and the pending corrections (`WritingStyle`: `writing-style-corrections.json`, last 20, from `DraftCorrections`, the draft put in a chat's box against what was sent there). While it searches the web the working line says so (`aiButton.searchingWeb`). Drafts and fixes (⌘O) carry the file; Ajustes → Escribir con IA shows and edits it. A finished draft or fix plays a short sound (`assist/ReadySound`, synthesized in Java so Windows sounds the same; `ai.readySound` CHIME|SOFT|BELL|OFF, `ai.readyVolume` 0–100; never on a failure or cancel; surefire sets `unichat.silent`). From anywhere in the window ⌘I writes and ⌘O corrects (`Composer.aiKeyPressed`), leaving the focus in the text box; the info panel is ⌘⇧I. Chats are written by others and can carry instructions: keep the CLI's tools minimal (`AiEngine.command`: Claude reads only the chosen folder, tested by `ReplyWriterTest` with `-Dunichat.networkTests=true`) and never log the prompt.

## Lessons
- Codex got only `--sandbox read-only`, while the person's `~/.codex/config.toml` (MCP servers, which run outside its sandbox), exec rules and the chosen folder's AGENTS.md still applied: a message's hidden instruction could drive them. `AiEngine.command` gives Codex the same isolation as Claude: `--ignore-user-config --ignore-rules -c project_doc_max_bytes=0` (Codex 0.161+; `ReplyWriterTest`). Whatever a new engine is, it runs with none of the person's own tools or config.
