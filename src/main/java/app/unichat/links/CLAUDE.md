# links — notes for Claude

`LinkInspector` opens the links in messages to find out whether they hold video or audio. The links come from anyone: no cookies, every hop (redirects included) refuses this machine and its network (loopback, private, link-local and reserved ranges: 100.64/10, 198.18/15, 192.0.0/24, 240/4; an IPv6 that carries an IPv4, 64:ff9b::/96, 2002::/16 or ::/96, is judged by that IPv4), and every body is read through `support/BoundedBody`: a size cap and a deadline (20 s for inspecting, 1 h for a download), since `HttpRequest.timeout` covers only the headers and a server trickling bytes held one of the 4 threads for good. At the deadline the body is closed, which wakes the blocked read. The deadline is a package-private constructor argument: tests give `Duration.ZERO` against a server that never finishes. The checks lean on the JVM's DNS cache between checking and connecting. More in `.claude/rules/ui-timeline.md`. Where what it finds is shown, and the embed HTML around it: `ui/timeline/CLAUDE.md`.
