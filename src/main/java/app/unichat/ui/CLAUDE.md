# ui — notes for Claude

JavaFX screens: the only package (with the root) that uses JavaFX. Topics with their own notes, loaded with their files (`.claude/rules/`): `ui-timeline.md` (the open chat, message HTML), `ui-media.md` (photos, video, audio, animations), `ui-emoji.md`, `ui-settings.md` (the settings window), `macos-desktop.md` (Dock, tray, menu bar, quitting), `css-icons.md` (app.css, `Theme`, `Icons`). A screen of a feature package (cloud, autosave, assist, cloak, voice, login) follows that package's `CLAUDE.md` too. To look at a change: the `snapshot` skill.

## Map
- `MainView` (rail | `ChatListPane` | `ThreadPane` + `InfoPane`, overlays; keys, F6 and zoom in `WindowShortcuts`), `ChatListPane` (+ `ChatRowCell`, `SpaceChannelsView`), `ThreadPane` (+ `TimelineScroll`, `MessageRowView`, `MessageLine`), `Composer`, `CommandBar`, `AccountsPane` (+ `DiscordServersPage`, `LoadingView`), `SettingsWindow`, `Notifier` (AWT tray), `Theme`.
- Pure logic with tests: `A11yText` (what a screen reader and the voice say), `ChatFilter`, `ThreadRows`, `RichText`, `Formats`, `MediaSizes`, `LoginTexts`.
- Shared bits, use them instead of writing another: `Nodes` (show, style), `Labels.help`, `Chips.sticky`, `Icons.iconButton`, `MediaTile`, `SearchFields`, `WorkingLine`, `ListRows`.
- Listeners from `ChatService` come on any thread: marshal with `Platform.runLater`, coalesced in `MainView` by `Throttle`.

## Lists and redraws
- Lists never `setAll` the same rows nor call `ListView.refresh()` on a data change (`ListRows`): both pile every cell and hand them out again in another order, so each row draws another chat and the whole list repaints; rows redraw in place (`ListRows.Redrawable`). Redraws touch only what changed: each change redraws the visible rows (opening a chat marks it read), so a row (`ChatRowCell`) keeps its nodes and only toggles them (flag icons, account tag), `Avatar` keeps one network icon per network, `Rail` keeps its unread badges, the favorites row is rebuilt only when its chats change, and `Nodes.style` leaves classes alone when already so. `ListRepaintUiTest` checks it.
- `InfoPane` is built again only when what it shows changes (`InfoPane.shown`): the window refreshes it on every message, and rebuilding blanked its photos (a flash). Its "Multimedia" is `ProfileMedia` (tabs in equal shares, the icon over its count: five side by side with two-digit counts were cut and uneven, `ProfileMediaTabsUiTest`): photos, videos, audio (voice notes and music, with the window's `AudioPlayback`), links and files in tabs (`ProfileMedia.Contents`, pure, newest first), photos whole in their square (`MediaTile` keeps the ratio), hidden per chat from its options (`ChatPreferences.setMediaHidden`, `Flag.MEDIA_HIDDEN`). From any of them to the message it came in (`ThreadPane.jumpToMessage`): a photo's or video's menu (right click, the menu key; a click views it), a link's or file's own button.
- Don't build nodes while the window is hidden: nothing is drawn, so JavaFX never empties `Scene.dirtyNodes` and everything built stays in memory (`MainView.catchUp` brings it up to date on opening; only the menu bar count updates meanwhile).
- Opening a file with the system's app goes through `Browser.openFile` only (AWT's own thread; `open`/`start`/`xdg-open` where AWT's Desktop can't; a message when there's no way): called from the thread a download finished on, it did nothing at all on macOS (`FileOpenUiTest`).

## Accessibility (user requirement — keep it working)
- Settings → Accesibilidad (`a11y.*` keys); `Theme` adds `contrast`, `strong-focus`, `wide-spacing` root classes and follows OS high contrast / reduced motion. Every new control needs an accessible text (icon buttons get it from `Icons.iconButton`), keyboard reachability, and must survive 160 % text + high contrast. Icons grow with the text (`Icons.SCALE`, set by `Theme`): give paddings that make room for one in `em`, and check alignment with the `snapshot` skill at scale 2 and `ui.fontScale=1.6`.
- The message box is as tall as the text it draws (its own Text node, measured after each layout and when the text re-wraps: guessing from the font size cut lines), up to 40 % of the window, then scrolls (`ComposerHeightUiTest`). Notices (`MainView.toast`) sit just above the message box, never over it (`ToastPlacementUiTest`). The composer puts the text on its own line above the buttons when they'd leave it under 14 em (`Composer.stack`, decided in a runLater after the layout that changed the width: moved mid-layout, the frame kept the stacked height; `NotificationOpenUiTest`).
- The info panel's six actions are round icons (names in tooltips and for screen readers: mute, favorite, pin, archive, low priority and the chat's options), all in a row or three and three, never five and one (`ActionGrid` decides from the width it gets and says its height depends on it; a TilePane's insets and rounding gave 2-2-2 and 5-1; `InfoActionsLayoutUiTest`, `InfoActionsUiTest`); leaving the group or deleting the chat is in the options, on their own "Peligroso" tab ("General" has the everyday ones; both stay built, only one shows) and behind a second "yes", never at hand (`ChatOptionsUiTest`).
- The composer has one media button (the face): it opens the side panel on the media tab used last (`SidePanel.lastMediaTab`, `panel.mediaTab`, default Emojis); a sticker or GIF's right-click menu has "Ver en grande" (`LibraryMenu.enlarge`). A plain key pressed outside a text box with a chat open writes in the composer (`WindowShortcuts.typeIntoComposer`, a handler so the timeline's own keys win). ⌘L (Ctrl+L) goes to the message box from anywhere. Every search box has a ✕ (`SearchFields`, out of the Tab order) and Esc empties it before closing what it's in. A message's menu (Enter on it) has what only the mouse could do: view its photo/video, go to the message it answers, open its links (`MessageActionsUi`).

## Lessons
- Avatars flashed on every inbox refresh: recycled cells hid the photo and reloaded it (a background-loaded `Image` is blank until decoded). Then, cached per size, one contact at 44/34/28/84 px still missed the cache on every click. Now `ImageCache` keeps one decoded 168 px image per URL for every size, loads are de-duplicated, failed URLs aren't retried per click, and the 150 most recent chats' photos are preloaded (`AvatarFlashUiTest`).
- A reused empty `ListCell` kept the `:current` pseudo-class → a grey "selected" bar under the list. Reset pseudo-classes in the empty branch of `updateItem`.
- List cells must use `setPrefWidth(0)` so they size to the viewport instead of content: the timeline's `RowCell` missed it and, with the side panel open, one wide row stretched every cell and cut outgoing bubbles at the right edge.
- `LoginWebView`: JavaFX's WebView keeps the first CookieHandler it saw for the whole process (`HTTP2Loader.HTTP_CLIENT`), so a second login window never saw its cookies. `LoginWebView.CurrentCookies` stays installed and forwards. More in `login/CLAUDE.md`.
