# ui.settings — the settings window, notes for Claude

The window (Ajustes) over the preferences of `settings/` (`settings/CLAUDE.md`, which points here): `SettingsWindow`, `SettingsForm`, `SettingsRow`, the pages, `ConverterSettings`, `SyncedSettings` (what applies live when settings arrive from the cloud), `CloudTexts` (the cloud's status in the same words everywhere).

- `SettingsWindow`: pages built with `SettingsForm`: each option a `SettingsRow`, its control beside the text while the text keeps 14 em, under it otherwise (a wide one squeezed names to a syllable a line); `SettingsLayoutUiTest` checks every page at 100 % and 160 %; `stacked` always puts it under.
- Redes puts what holds for every network first, then each network by name, with the converter in `ConverterSettings`. Pages: `AppearancePages`, `PrivacyPage`, `NetworksPage`, `SpeechPage`, `AiReplyPage`, `CloudPage`, `AboutPage`.
- A new setting key: `SyncedSettingsUiTest` has a proof for every setting key in the source and fails for a new one without (it travels with the person's cloud, `cloud/CLAUDE.md`); keys that must stay on this machine are `Settings.staysOnThisMachine`'s (`service/CLAUDE.md`).
- A new connection to anything outside the machine is in `docs/PRIVACY.md` and `docs/PRIVACIDAD.md` and can be turned off here (`packaging/CLAUDE.md`, SignPath's terms).
- Nube → Bóveda (`VaultPage`, under the connected account): each state drawn from `Cloud.vaultView` (none: "Crear bóveda"; locked: `VaultOpenForm` and "Seguir sin la bóveda en este equipo"; declined: a line and "Abrir la bóveda"; removed: says so and `VaultOpenForm`; open: ways in, computers, new code, change the key, forget here, turn it off: asked twice, first whether, then what happens with the button saying the action; a working line while it runs, and on failure the vault read again: still open, why and "Intentar de nuevo"; off all the same (its folder partly left), the page as it is with why). A step under way (a code on screen, a confirmation) is never redrawn by a round. `RecoveryCodeSheet` shows a code once (non-editable, selectable; copy, save as .txt and print through hooks tests replace) and asks two random groups back; stopping before leaves the vault made but says the code must be kept. `KeyChangeFlow`: "Quitar este equipo" and "Cambiar la llave" read the computers again (the page may be old) and list who gets the new key, flagging one new since the last removal or never seen here and one whose key changed (it gets nothing; "Aceptar su nueva llave", asked once more, only before the change: after it, its key is sealed with the old one); only the computers listed are offered the key (`Cloud.rotateKey(confirmed)`), one that comes after is named; then the new code, the ways in that went ("Agregar de nuevo") and who was refused. Computers' names come from the account: shown only through `CloudTexts.computer` (`VaultView.label`: one line, 64 characters), as Labels, never markup or a path. Secrets in `PasswordField`s, emptied as soon as they go. `VaultPageUiTest`.

## Lessons
- Ajustes → Nube's status line stopped listening to the cloud when its node left its scene, but a closed window keeps its scene: every closed settings window heard each round for good, reading `CloudPage`'s static `cloud` (null in a later session: an exception on the UI thread each round). A page listens through `Showing.whileShowing`, with the `Cloud` it was built with (`VaultPageUiTest.aClosedWindowNoLongerHearsTheCloud`).
- `VaultPage` added "the vault is off but part of its folder was left" above the page by hand, and a round's mid-way `doing()` (which still carries the last state, OPEN) made the page reload and drop it: `VaultPageUiTest` timed out only in the full run. A line that must outlive a redraw is page state (`notice`, drawn by `draw` while the page shows its state), never a node added after drawing.
- `VaultPage` drew every `reload` answer: closing the code sheet started one, and a round saying the state changed (the page still showing NONE) a second, which landed after "Olvidar la bóveda en este equipo" had opened and drew the open page over it (`VaultStatesUiTest.forgettingTheOnlyComputer…`, timing out on one machine for good). Only the last reload asked for draws, and none over a step begun since (`asked`, `inStep`; `VaultPageUiTest.aLateReloadNeverDrawsOverAStepBegunSince` holds the reload's read to force the order).
