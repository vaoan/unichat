# cloak — notes for Claude

Protecting a photo from AI training before sending it.

- Protected photos (clip → "Foto protegida contra IA…", `ui/timeline/CloakSend` + `CloakBar`, `cloak/`): Mist's textural attack written anew (Mist is GPL, Unichat 0BSD: no code of theirs), `resources/app/unichat/cloak/cloak.py`: PGD on Stable Diffusion 1.x's image encoder only (34M parameters; the encoder alone was checked against the original to 6e-5) toward Mist's target pattern, in tiles of at most 256 px at up to 768 px per side, so memory stays ~1.5 GB whatever the picture (the person's hard limit is 4 GB: the script stops itself past it, `check_memory`). The full Mist (with the diffusion network) needs ~12 GB and didn't fit an 8 GB Mac. `CloakLevel` LIGHT/MEDIUM/STRONG = 10/30/100 steps (~3/8/25 min on an M1). `cloak/CloakTool` installs on first use into `<data>/tools/cloak/`: pinned uv, which brings Python 3.12 and `requirements.txt` (exact versions with hashes, `--require-hashes --no-build`, regenerate with `uv pip compile --generate-hashes --exclude-newer <2 weeks ago>`), plus the encoder weights (Hugging Face) and `MIST.png` (GitHub), both pinned; bump `CloakTool.VERSION` when any of it changes. `cloak/CloakJob`: one at a time for the app, cancellable; the result goes as a `DOCUMENT` through `UploadQueue`. Only Apple-chip Macs and 64-bit Windows (PyTorch has no Intel Mac build). `CloakToolTest` with `-Dunichat.networkTests=true` installs for real and protects a picture.

## Lessons
- A cancelled job's thread can take a while to stop (a download doesn't end at the interrupt): after cancel, dismiss and a new start, its late reports wrote over the new job's status, since `update`/`finish` only checked `busy()`. Each start gets an id and only its own thread's reports are taken (`CloakJobTest.anOldJobStoppingLateDoesntWriteOverTheNewOne`). The script's silence limit is `Processes.Limit.whileTalking`, not a loop of its own over unsynchronized arrays.
