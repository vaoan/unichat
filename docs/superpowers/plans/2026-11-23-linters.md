# Every free linter, enforced — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development.

**Goal:** every free Java quality tool runs on `./mvnw verify` and fails it, with all existing findings fixed.

**Spec:** `docs/superpowers/specs/2026-11-23-linters-design.md`. Read it whole: the tool table, the adoption rules and the phases.

## Global Constraints
- **A tool fails the build.**
  - It runs in `verify`, locally and in CI; the exceptions are Dependency-Check and CodeQL, which run in CI only.
  - A tool's warning that can be made an error is made an error.
- **Every finding on the existing code is fixed.**
  - No exclusion of whole rules, packages or files.
  - No baseline file.
  - A suppression is narrow (one line, one member) and carries its reason on the same line: `@SuppressWarnings("x") // why`, `// NOPMD: why`, or SpotBugs `@SuppressFBWarnings(value=…, justification="…")`.
  - A rule may be left out of a ruleset only if it is noise for this codebase, with a one-line reason in the config. Examples of noise: rules that demand `final` everywhere, or a specific formatting style. Leaving a rule out is a decision the reviewer checks.
- **Fixes don't change behaviour.**
  - The full `./mvnw clean verify -Pheadless-ui` stays green.
  - A finding that is a real bug gets its own test that fails first, and one line in the folder's `CLAUDE.md` Lessons.
- **Build time:** measure `verify` before and after each task, and report both. The local `verify` must stay under 2× its time before Task 1. Use the tools' incremental or cache options.
- **Versions:** plugin and tool versions are pinned (Enforcer checks it). They must support Java 25.
- **Mutations:** when breaking code on purpose to watch a test fail, use a throwaway `git worktree add` under the session scratchpad, never the person's working tree. The rule goes into `src/test/CLAUDE.md` in Task 1.
- **Commands:** run in the foreground. A long run goes class by class or in parts, never as a background job.

## Tasks
1. **javac `-Xlint:all -Werror`, Maven Enforcer, Modernizer.**
   - Configure all three, fix every finding, and add the mutation rule to `src/test/CLAUDE.md`.
   - Test: a `BuildRulesTest` that reads `pom.xml` and asserts these plugins and flags are on, so nobody can quietly turn them off.
2. **Error Prone.**
   - Use the javac plugin and turn its warnings into errors (`-XepAllErrorsAsWarnings` off, `-Werror`).
   - Fix everything.
   - Extend `BuildRulesTest`.
3. **PMD, with a full rule set.**
   - Write `pmd-rules.xml`: the bestpractices, codestyle (minus the formatting-only rules, each left out with a reason), design, documentation (minus the comment-count rules), errorprone, multithreading, performance and security categories.
   - Fix everything.
   - Add a `SuppressionsHaveReasonsTest` that scans the sources for `NOPMD` and `@SuppressWarnings` without a reason.
4. **SpotBugs with FindSecBugs.**
   - Effort Max, threshold Low.
   - Fix everything, then extend `BuildRulesTest`.
5. **Full Checkstyle.**
   - Extend `checkstyle.xml` with the checks that catch defects or clarity problems rather than layout: `EqualsHashCode`, `MissingSwitchDefault`, `FallThrough`, `ModifierOrder`, `RedundantModifier`, `UnusedImports`, `AvoidStarImport`, `OneStatementPerLine`, `MultipleVariableDeclarations`, `StringLiteralEquality`, `SimplifyBooleanExpression`, `SimplifyBooleanReturn`, `InnerAssignment`, the naming checks matching today's style, `EmptyCatchBlock` and `HiddenField` (for constructors and setters as the code uses them).
   - Fix everything.
6. **JaCoCo.**
   - The coverage report runs on every build.
   - A rule fails a package whose line coverage falls below its measured value at this commit, rounded down to the nearest 5 %.
   - Write those values into the pom with a comment saying how to raise them.
7. **NullAway with JSpecify.** NullAway in mode `@NullMarked` per package; add the JSpecify dependency.
   - Go package by package, in this order: `support`, `model`, `settings`, `service`, `cloud`, `matrix`, `server`, then the rest.
   - Each package gets `package-info.java` with `@NullMarked`, plus `@Nullable` where null is meant.
   - Fix every finding.
   - This task may be split into several commits; one commit per package group is fine.
8. **CI.**
   - Add `.github/workflows/codeql.yml` (java, on push and PR, `security-and-quality` queries).
   - Add OWASP Dependency-Check as a job in `build.yml`: cached, fails on CVSS ≥ 7, with a suppressions file where each entry has a reason.
   - Follow `.github/CLAUDE.md`: actions pinned by SHA, no `${{ }}` in `run:`, minimal permissions.
