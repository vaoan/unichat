# Null (NullAway, JSpecify)

- Every package has a `package-info.java` with `@NullMarked` (each subpackage its own): one with main code in `src/main/java`, one only tests have (`app.unichat.build`) in `src/test/java`. The one exception is `app.unichat.claude` (`NullMarkedTest.UNMARKED`): the hooks run its programs with Java's source launcher and no classpath (`.claude/hooks/java.sh`), so it has no package-info and nothing there uses JSpecify; `HookLauncherTest` runs one the hooks' way. A new package needs one from its first class: `NullMarkedTest` reads every package under both, the mark however it is written, and fails on one without it, on a test-side `package-info.java` for a package with main code, and on a class marked by itself. Its test classes share the package's mark, so NullAway checks them too. Nothing is `@NullUnmarked`.
- In a marked package a type without `@Nullable` (`org.jspecify.annotations.Nullable`) never holds null. Write `@Nullable` where null really is a value: a field set later, a "null when none" return, a parameter the code checks for null. Put it on the type: `java.nio.file.@Nullable Path`, `List<@Nullable String>`, `String @Nullable []`.
- Fixes keep behaviour: annotate truthfully and handle the null, rather than invent a default. Make null impossible only when nothing changes (`getOrDefault` on a map's own keys).
- A record component that its compact constructor turns from null into a value (`Contact.identifiers`, `LinkPreview.title`) stays non-null: `@Nullable` there would make its accessor nullable too. A caller passes the empty value instead.
- `Settings.getString(key)` is "null when unset"; `getString(key, def)` takes a non-null default. A marked caller of `getString(key, null)` moves to the first.
- A listener told null (`Settings.addListener`: "many keys changed") is a `Consumer<@Nullable String>`.
- Tests: JUnit's `assertNotNull(x)` tells NullAway `x` isn't null (`HandleTestAssertionLibraries`). A test that passes null on purpose to see it refused carries `@SuppressWarnings("NullAway") // why` on that one method.
- A job that answers null for `Void` (`Cloud.Job`, `CloudVault.withKey`): the type parameter is `<T extends @Nullable Object>` and the method gives `CompletableFuture<@Nullable Void>`, or the lambda's `return null` is refused.
- A field null only in a mode where the code reading it never runs (`PreferencesFile.inMemory`'s paths, `VaultParts.Round.info()` while not open): pass the checked value on (`load(Path)`), or read it through `Objects.requireNonNull(field, "why")`, which fails as the dereference did. Never a default.
- A getter read twice (`x.f() != null && x.f().g()`) goes through a local: NullAway takes it, SpotBugs (`NP_NULL_ON_SOME_PATH_FROM_RETURN_VALUE`) doesn't. That pattern is on for the whole code and `BuildRulesTest.spotBugsNullChecksAreNeverLeftOut` fails if `spotbugs-exclude.xml` leaves it out again, by its name in a list, a `~` regex, the code `NP` or the category `CORRECTNESS`. A comparison reads the value once from the other side: `chatId.equals(currentChatId())`, `String.valueOf(m.fileName()).startsWith(…)` in a test.
- An override of a `@Nullable` method (a wrapper such as `OldVault`, a test's `Through` or fake) says `@Nullable` too.
- Tests: `app.unichat.Present.of(x)` for a value the test goes on with (`svc.chat(id)`, a file's bytes, a slot), `Present.message(e)` for what a failure wrapped says; a field a helper every test calls sets carries `@SuppressWarnings("NullAway.Init") // why`.
- NullAway's own annotations (`com.uber.nullaway.annotations.MonotonicNonNull`, `EnsuresNonNull`, `RequiresNonNull`) are not JSpecify's: they need `com.uber.nullaway:nullaway-annotations` as a dependency, which the repo doesn't have. No marked package has needed them: a field set later is `@Nullable` and read through a local or `Objects.requireNonNull(field, "why")`.
- JSON from the homeserver or a bridge (Jackson's `asText(null)`, `get`) is a stranger's: NullAway takes an unmarked library's answer as non-null, so the field, parameter or future that holds it says `@Nullable` (`MatrixRoom.name`, `SyncProcessor.confirmLocalEcho`'s event id, `CompletableFuture<@Nullable String>` from a send). A missing field is skipped or defaulted as before, never thrown on: the sync loop reads it.
- `Set.of(…)`, `List.of(…)` and `Map.of(…)` throw on `contains(null)`/`get(null)`: a nullable value is checked before it's looked up (`NetworkFormats.sticker`).
- Generic helpers that may answer null (`MatrixCore.call`) take `<T extends @Nullable Object>`, so a `Callable` that returns null is accepted.
- A test field a request handler sets (`SendStickerTest.path`) is `@Nullable` and read with `Present.of`; one each test sets before use and `@AfterEach` checks carries `@SuppressWarnings("NullAway.Init") // why`, which lambdas can read too.
- A tool this computer may lack (`Ffmpeg.find()`, `AnimDump.find()`): a test takes it through `app.unichat.Present.orSkip(x, "no ffmpeg")`, which skips the test when it's null and gives it back non-null; NullAway doesn't read `assumeTrue(x != null)`.
- An override of an unmarked library's method that answers null (`WebSocket.Listener.onText`, InstaTray's `Fetch.Tools.ffmpeg()`) says `@Nullable` on its return; a getter of such a library read twice goes through a local too.
- A field a method sets and then hands on (`ChromeLogin.process`) is passed to the helper as the checked local (`awaitDebugPort(started, port)`), not read back from the field.
- `I18n.t`'s arguments are `@Nullable Object...`: an exception's message goes in as it is and shows "null" as before. A cleaner text is a behaviour change with its own test (`Errors.message`).
- A helper that answered null only for a null input (`ReplyPrompt.withoutMarks`) takes and gives non-null; its caller decides what a missing value is (`written == null ? "" : …`).
- JavaFX answers null before a node is shown (`getScene()`, `getWindow()`) and on an empty cell (`updateItem(item, empty)`): JavaFX isn't marked, so NullAway can't see it. `ui/Nodes.window(node)` gives the window or null, read once into a local; a `Supplier<@Nullable Window>` says the same to whoever is handed it; a cell keeps its `empty || item == null` check.
- A field the FX or AWT thread sets after construction (a stage built on first show, the tray's menu, a `MediaPlayer`, `Timeline` or `PauseTransition`) is `@Nullable`, made into a local first, stored, then used from the local (`MediaPlayer p = MediaPlayers.open(…); player = p; if (p == null) return;`). One the constructor can make is made at its declaration instead (`ChatListPane.newChat`).
- A JNA binding (`WindowsScreenWindow`) says `@Nullable` where Windows takes or gives NULL (a pointer argument passed as null, a handle that can fail); a check that throws on null goes in a helper method (`createWindow`), since `check(p != null, …)` tells NullAway nothing and a `throw` inside the `try` that undoes it is PMD's ExceptionAsFlowControl.
- `MediaSource.media` and `sticker` take a `@Nullable` url: no address gives a failed future ("error.noUrl"), as `MediaDownloader.fetch` and the mock always did, so a screen passes `m.mediaUrl()` as it is and shows the failure. Where the caller knows the address is there (`Message.playsInline`, the actions offered only with one), the code says why with `requireNonNull`.
- Error Prone's BadInstanceof refuses `x instanceof T t` when `x` is already a `T` (`m.mediaUrl() instanceof String`): a local and `!= null` instead.
- SpotBugs refuses a `@Nullable` parameter the method itself `requireNonNull`s (NP_PARAMETER_MUST_BE_NONNULL_BUT_MARKED_AS_NULLABLE): the parameter stays non-null and the caller says why (`ChatOptions.day`). A suppression the local made needless goes (SpotBugs' US_USELESS_SUPPRESSION_ON_METHOD: LI_LAZY_INIT_STATIC, UWF_FIELD_NOT_INITIALIZED_IN_CONSTRUCTOR, NP_BOOLEAN_RETURN_NULL on a `@Nullable Boolean`; PMD's UnnecessaryWarningSuppression for a NOPMD).
- A test that can't make what a parameter wants headless (an AWT `PopupMenu` for `NativeBar.start`) passes null under `@SuppressWarnings("NullAway") // why` on that one method; a field set inside `FxWait.fx` by the `@BeforeEach` carries `@SuppressWarnings("NullAway.Init") // why`.
- `FxWait.fx` (and a test's own `fx` wrapper) takes `<T extends @Nullable Object>`: what JavaFX answers null (a `lookup`, `SettingsWindow.current()`) comes back as it is, and the test goes on with it through `Present.of`. Work without a result is `FxWait.onFx(() -> …)`, never `fx(() -> { …; return null; })` (`src/test/CLAUDE.md`). Where inference picks a non-null `T` for a method reference that answers null, the call names it: `FxWait.<@Nullable Double, RuntimeException>fx(this::newestGap)`.
- A JavaFX `Application`'s fields that `start()` sets before anything else runs (`UnichatApp.stage`, `scene`, `notifier`) carry `@SuppressWarnings("NullAway.Init") // why`. A field a helper the constructor calls would set is returned by the helper to the constructor and made `final` instead (`ThreadPane.header`, `headerButtons`). One that goes back to null (the session's service, the main view on the login screen) is `@Nullable` and read through a local, also inside a lambda that runs later (`MainView view = mainView; if (view != null) …`).
- A class whose parts are null by kind (`SendQueue.Entry`: a text, or another send) becomes a `sealed interface` with one type per kind (`Text`, `Action`), each with only non-null parts; code that wants one kind takes that type (`find` gives a `Text`).
- A result that is one value or the other (`Correction.Result`: the text, or why it failed) has both `@Nullable`; the caller reads the one it goes on with into a local and tests that (`String fixed = r.text(); if (fixed != null) …`).
- A page that outlives the session it was built in reads the session's object again when it acts (`CloudPage`'s redraw and connect read `cloud` into a local, and do nothing without one: `CloudPageUiTest`), never the one it was built with.
- The open chat handed around is a `Supplier<@Nullable Chat>` (`ThreadPane.chat`); a button or menu that only shows with a chat open reads it into a local and does nothing without one. A diagnostic that needs one (the snapshot's `show*`) says so with `requireNonNull` (`ThreadPane.shownChatId`).
- `Present.orSkip` ends with `Assumptions.abort(why)` when there's nothing: NullAway reads that, not `assumeTrue`. Inside `FxWait.until`, `Present.of` failing counts as "not yet", as the NPE it replaces did.
