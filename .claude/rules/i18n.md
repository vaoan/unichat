# Texts the person reads

- Every user-facing text goes through `support/I18n` (`I18n.t("key")`, `I18n.n` for counts): `src/main/resources/app/unichat/i18n/messages.properties` (English, the fallback) and `messages_es.properties`. A new language is one more `messages_<code>.properties` (found by `I18n.available`, offered in Settings → Appearance); `I18nTest` demands the same keys and placeholders in every file.
- The language changes live (`UnichatApp.relocalize` rebuilds the window), so never keep a text in a `static final` or anything built once.
- English first: what Unichat stores, sends, logs or tells a program (file and folder names, cloud paths, ids, log lines, AI prompts, errors that aren't shown) is English, whatever the UI language. Spanish reaches the person only through `messages_es.properties`. A demo name, a snapshot draft or an example the person reads is UI: a key in both files (`demo.*`, `settings.speech.commandExample`).
- `EnglishFirstTest` reads every string literal and text block under `src/main/java` (not comments, not `support/I18n`) and fails on Spanish: `áéíóúñ¿¡` or a common Spanish word, as a whole word. A literal that must stay (an old cloud name the migration looks for, an old placeholder a saved command may still have, the account name existing local servers have) goes in its `ALLOWED` list: one entry per file and literal, with its reason, matching that literal exactly (`Allowed.part` only where one name sits inside several literals or a long prompt). What people write (chat text, names, fixtures in tests) may be in any language and isn't checked.

## Lessons
- Spanish lived on in what isn't UI long after the UI went through I18n: demo names, the settings page ids (`"Cuentas"`), cloud folder names, and the setup scripts' messages (`"Descargando…"`). `EnglishFirstTest` now reads every Java literal and the `script-spanish` lesson the `.sh`/`.ps1` messages; a text the person reads is a key in both files, anything else is English.
