# packaging — notes for Claude

Packages, releases, versions, signing and third-party notices (package.sh, package.ps1, .github/ at the root). The rules, commands and map are in the root `CLAUDE.md`.

- `THIRD-PARTY.md` — generated by `native/third-party.py` (rerun when a dependency or pinned version changes); shipped
  with `LICENSE` in the packages. Unichat's own code is 0BSD.
- Code signing (Windows): applied to SignPath Foundation's free OSS program (README «Code signing policy», required wording and roles; every release page links it from build.yml). Their terms: whatever reaches a system the person didn't choose is in docs/PRIVACY.md, shown before installing (`packaging/install-notice.txt`, the .msi's license page; keep it true when adding a connection) and can be turned off in Ajustes. Once approved: their GitHub Action (`signpath/github-action-submit-signing-request`) in build.yml's windows job, with the secret `SIGNPATH_API_TOKEN`, their organization id and project/policy slugs, signing the zip's contents and the .msi before release; product name "Unichat" and the pom's version must match (`--name`, `--app-version`). macOS isn't covered: notarizing needs an Apple Developer account.
- macOS minimum: `MACOS_MIN` in package.sh (13.3, whisper-cli's), passed to every native build (swiftc otherwise targets the Mac it runs on) and written to Info.plist; `native/check-macos-min.sh` fails the package if any binary inside needs more.
- `package.sh` / `package.ps1` — jpackage, version read from the pom; `.github/workflows/build.yml` builds Windows zip/msi + macOS dmg, and a tag `v<pom version>` publishes them as a GitHub release (a `-suffix` tag is a pre-release, which the update check skips).
- Version: the pom's, read at run time from the filtered `version.properties` (`support/AppVersion`; "dev" when unfiltered, never offered an update). `update/UpdateChecker` asks GitHub's latest release once a day (`app.checkUpdates`, Ajustes → Privacidad; `app.update.*` stay on this machine), `ui/UpdateBar` says so at the foot of the chat list; any failure is one log line. Ajustes → Acerca de (`ui/AboutPage`): check now, open the logs folder, copy an error report (`support/ErrorReport`: version, system and the log's last lines, redacted again). Cuentas → Agregar cuenta warns that networks don't authorize bridges.
- `.github/workflows/natives.yml` — what has no official build: tuwunel for both platforms and the bridges for Windows (cross-compiled from Linux with MinGW, `-tags goolm`; Discord's legacy bridge also `nocrypto` and a newer zeroconfig), published as the release `NATIVES` in `versions.env` names; `NATIVES_UNBUILT` (Signal) is what Windows can't offer (`Manifest.builds`). Bump `NATIVES` with any version change. `native/fetch-natives.sh` and package.ps1 put its tuwunel in the app. Users download from it, which is why the repository is public (since 2026-11-09).
